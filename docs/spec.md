## 1. 用户注册 / 登录

### 1.1 目标

实现校园用户的身份认证系统，支持基于 JWT 的无状态鉴权，区分普通用户和管理员角色。

### 1.2 边界

- **包含**：用户名密码注册、登录、JWT 签发、Token 验证、角色区分、用户信息查询
- **不包含**：OAuth 第三方登录、邮箱验证、短信验证、密码找回

### 1.3 前置条件

- 用户尚未注册时，注册接口可用
- 数据库 users 表已初始化

### 1.4 正常流程

**注册**
1. 用户填写 username（唯一）、password（>=6位）、nickname（显示名）、contact（选填）
2. 系统校验参数格式
3. 系统检查用户名是否已存在
4. 密码经 bcrypt（salt rounds=10）加密存储
5. 签发 JWT（有效期为 7 天），含 userId、username、role
6. 返回 201 + JWT + 用户信息

**登录**
1. 用户提交 username + password
2. 系统查询用户
3. bcrypt 校验密码
4. 签发 JWT
5. 返回 200 + JWT + 用户信息

**鉴权**
1. 客户端在 Authorization 头携带 Bearer token
2. 服务端解码 JWT 获取用户身份
3. 过期或无效 Token 返回 401

### 1.5 异常流程

| 场景 | 响应 |
|------|------|
| 用户名已存在 | 400, code=40001 |
| 用户名或密码错误 | 401, code=40101 |
| 无 Token 访问受保护接口 | 401, code=40101 |
| 非管理员访问管理接口 | 403, code=40301 |

### 1.6 验收标准

- 注册新用户成功返回 201 + JWT
- 重复用户名返回 400
- 正确凭证登录返回 200 + JWT
- 错误密码登录返回 401
- 携带有效 Token 可获取用户信息
- 无 Token 返回 401
- 管理员 Token 可访问管理接口
- 普通用户 Token 访问管理接口返回 403

## 2. 商品发布

### 2.1 目标

允许已登录用户发布闲置商品信息，提交后进入管理员审核流程。

### 2.2 边界

- **包含**：商品标题/描述/价格/分类/图片/联系方式的填写与提交，参数校验
- **不包含**：图片文件上传（仅存储 URL）、富文本编辑器、草稿保存

### 2.3 前置条件

- 用户已登录（拥有有效 JWT）
- 分类数据已初始化

### 2.4 正常流程

1. 用户填写 POST /api/goods 请求体
2. 系统校验：标题必填（<=100字）、价格必填（>0）、分类默认"其他"
3. 商品状态自动设为 pending（待审核）
4. 返回 201 + 商品 ID
5. 前端提示"发布成功，等待管理员审核"

### 2.5 字段规格

| 字段 | 类型 | 必填 | 约束 |
|------|------|------|------|
| title | string | 是 | 1-100 字符 |
| description | string | 否 | 默认为空 |
| price | number | 是 | > 0 |
| original_price | number | 否 | 原价 |
| category_id | number | 否 | 默认 6（其他） |
| images | string[] | 否 | 最多 5 个 URL |
| contact | string | 否 | 联系方式 |

### 2.6 验收标准

- 已登录用户可发布商品，返回 201
- 未登录用户发布返回 401
- 缺标题或价格返回 400
- 发布后商品状态为 pending
- 商品出现在管理员的待审核列表中

## 3. 商品浏览

### 3.1 目标

提供商品列表页，支持分页展示、分类筛选、关键词搜索和价格排序，覆盖四种 UI 状态。

### 3.2 边界

- **包含**：分页（12条/页）、分类筛选、关键词搜索、价格范围筛选、价格排序、四种 UI 状态
- **不包含**：自定义排序字段、无限滚动、多字段组合排序

### 3.3 四种 UI 状态

| 状态 | 表现 |
|------|------|
| Loading | 8 个 Skeleton 骨架屏卡片（渐变闪烁动画） |
| Empty | 居中空态插图 + "没有找到相关商品" + 建议文字 |
| Error | 红色错误提示 + 错误信息 + "重试"按钮 |
| Success | 商品数量统计 + 卡片网格 + 分页控件 |

### 3.4 验收标准

- 首页 SSR 渲染首屏商品列表
- 分页正常，每页 12 条
- 关键词搜索正确过滤
- 分类筛选正确过滤
- 价格范围筛选正确
- 价格排序（升序/降序）正确
- 无结果时显示空态
- 网络错误时显示错误提示 + 重试
- 加载中显示 Skeleton 骨架屏

## 6. 发起购买

### 6.1 目标

用户购买商品时，系统通过乐观锁确保库存一致性，防止超卖。

### 6.2 并发控制方案（三层防护）

1. **乐观锁（应用层）**：通过 version 字段实现 CAS
2. **部分唯一索引（数据库层）**：同一买家对同一商品只能有一个 pending_pay 订单
3. **状态机校验**：严格校验订单状态前置条件

### 6.3 下单流程

```
客户端 POST /api/orders { goodsId }
  1. 校验用户登录状态
  2. 校验请求参数
  3. 开启事务
     a. SELECT goods WHERE id=? AND status=approved AND stock>0
     b. UPDATE goods SET stock-=1, version+=1 WHERE id=? AND version=?
        -> 影响行数=0 -> 回滚 -> 返回 409
     c. 生成订单号（时间戳+随机数）
     d. INSERT INTO orders (order_no, goods_id, buyer_id, seller_id, price, status=pending_pay)
        -> UNIQUE 冲突 -> 回滚 -> 返回 409
     e. 提交事务
  4. 返回 201 + 订单信息
```

### 6.4 验收标准

- 下单成功返回 201 + status=pending_pay
- 库存为 0 时下单返回 409
- 未登录下单返回 401
- 100 并发抢 1 库存 -> 仅 1 单成功
- 同一用户重复下单同一商品 -> 第二次返回 409

## 7. 交易状态管理

### 7.1 目标

管理订单的生命周期，确保状态流转合法。

### 7.2 状态机

```
pending_pay --(付款)--> paid --(确认)--> completed
      |
      --(取消)--> cancelled（释放库存）
```

### 7.3 流转规则

| 当前状态 | 操作 | 目标状态 | 副作用 |
|----------|------|----------|--------|
| pending_pay | pay | paid | 无 |
| pending_pay | cancel | cancelled | 库存 +1 |
| paid | complete | completed | 无 |
| paid | cancel | cancelled | 库存 +1 |
| completed | - | - | 终态 |
| cancelled | - | - | 终态 |

### 7.4 验收标准

- pending_pay -> paid 成功
- pending_pay -> cancelled 成功，库存恢复
- paid -> completed 成功
- 终态订单不可再操作
- 只有买家可操作订单

## 10. API 契约

### 10.1 响应格式

```json
// 成功
{ "code": 0, "message": "success", "data": { ... } }
// 分页
{ "code": 0, "message": "success", "data": [...], "pagination": { "total": 42, "page": 1, "pageSize": 12, "totalPages": 4 } }
// 错误
{ "code": 40001, "message": "参数校验失败", "data": null }
```

### 10.2 错误码

| 错误码 | 含义 |
|--------|------|
| 0 | 成功 |
| 40001 | 参数校验失败 |
| 40101 | 未登录 / Token 过期 |
| 40301 | 无权限 |
| 40401 | 资源不存在 |
| 40901 | 并发冲突 |
| 40902 | 重复操作 |
| 50001 | 服务器内部错误 |

### 10.3 完整接口定义

详见 contracts/openapi.yaml（OpenAPI 3.0.3 格式，23 个接口）。
