## 三、并发测试详情

### 3.1 测试场景

模拟 **10 个用户、100 个并发请求**同时抢购 **库存为 1** 的商品，验证防超卖机制的有效性。

### 3.2 测试流程

1. 管理员登录 → 发布商品（库存=1）→ 审核通过
2. 注册 10 个压测用户，各自获取 JWT Token
3. 用 `Promise.all` 同时发起 100 个 POST `/api/orders` 请求
4. 统计各状态码分布
5. 验证最终库存和订单数据

### 3.3 测试结果

```
请求总数:     100
执行耗时:     291ms
✅ 下单成功:  1 次
⚡ 乐观锁拦截: 99 次（库存不足）
🔒 唯一索引拦截: 0 次（重复下单）
❌ 服务器错误: 0 次

最终库存:     0
相关订单数:   1
pending_pay:  1
```

### 3.4 防超卖机制分析

**第一层：乐观锁（应用层）**
```sql
UPDATE goods SET stock = stock - 1, version = version + 1
WHERE id = ? AND version = ? AND stock > 0
```
99 个请求被此层拦截，`changes === 0` 返回 409 错误码。

**第二层：部分唯一索引（数据库层）**
```sql
CREATE UNIQUE INDEX idx_order_unique_active
ON orders(goods_id, buyer_id) WHERE status = 'pending_pay'
```
防止同一用户对同一商品重复下单，作为乐观锁的兜底。

**第三层：取消释放库存**
取消订单时自动 `stock = stock + 1`，确保库存一致性。
